The **Skillist Registry MCP** server lets agents search, browse, and install skills without leaving the chat. It runs on the same API worker as the REST registry.

<DocAlert title="Endpoint" client:load>
  `https://api.skillist.dev/mcp` — streamable HTTP with optional OAuth.
</DocAlert>

Every request carries its protocol version and client info in `params._meta`
(`io.modelcontextprotocol/*` keys), mirrored into the headers above. Clients on
older revisions that open with `initialize` keep working — the handshake is
answered per request, with no session state. `server/discover` reports supported
versions and capabilities.

## Server info

```bash
curl https://api.skillist.dev/mcp
```

Returns transport metadata, tool names, and OAuth discovery URLs.

## Skills extension

Hosts that support the [Skills extension](https://modelcontextprotocol.io/extensions/skills/overview)
(`io.modelcontextprotocol/skills`) can load skills directly, without the CLI:

- `skills/get` and `resources/read` work for any public skill, at
  `skill://{org}/{repo}/SKILL.md`. No sign-in is needed.
- `skills/list` returns the skills you can load in projects you can read. It needs
  an authenticated MCP session, and is empty otherwise.

Each entry includes a manifest with the SHA-256 digest and byte size of every
file in the latest published version. Hosts receive a skill's files without running
them: sandbox **run** still uses the [CLI](/getting-started/cli/).

### Private skills

Private skills are off by default. An org owner can turn them on under **Governance**
with **Serve private skills over MCP**. Members of that org can then load the org's
private skills through an authenticated MCP session, and everyone else gets the same
"not found" as for a skill that doesn't exist.

Before you turn this on:

- **Every MCP client a member connects can read these skills.** MCP sign-in has no
  per-skill scopes, so a client gets whatever that member can read.
- **Access is per org, not per project.** A private project keeps a skill out of a
  member's `skills/list`, but any member can still load it by URI, as they can in the
  console.
- **Downloaded files can't be recalled.** Turning this off or removing a member stops
  new reads immediately, but a host keeps any copies it already has.

API keys stay anonymous on `/mcp`. To read private skills from CI, use the
[CLI](/getting-started/cli/) with a `skills:read` key.

## Public reads, scoped writes

The four `registry_*` tools are public, read-only registry access. The project
tools are gated by an authenticated MCP session and per-project access derived
from project visibility (`private`/`shared`) and membership: `my_projects`
returns only readable projects, `project_skills` needs read access (org owner, a
project member, or a shared project), and `add_skill_to_project` needs write
access (org owner, a project editor/admin, or an org editor+ on a shared
project). Publish, edit, and sandbox **run** still require the
[CLI](/getting-started/cli/) with an authenticated API key.
